# Overview

A PoC (Proof of Concept) proves a risky part of the system is feasible **before** full implementation. The complete set of PoC specs lives in [PoC Specifications](https://app.notion.com/p/PoC-Specifications-36ff29d2a6b181e1bd14d17ff0790d56?pvs=21).

# When to write one

- An integration or technique with real uncertainty (provider behavior, signed-URL flow, scoring approach).
- Anything we want to de-risk before committing to a phase.

# What a PoC must define

- **Goal** — the single question it answers.
- **Setup** — minimal scope, demo-mode friendly.
- **Success criteria** — measurable pass/fail.
- **Evidence** — where results are stored (`implementation-plan/evidence/`).

# Principle

- A PoC is throwaway-by-default: it proves feasibility, it is not production code.
