# testing/

Owner: Susank Shakya

<aside>
📁

**`docs/testing/`** — the test strategy across backend, the three frontends, storage, security, and end-to-end journeys — all verifiable in demo-mode.

</aside>

This folder documents how Nuvia Beauty is verified before promotion. Every layer is runnable without live provider credentials (demo-mode), produces evidence stored under `implementation-plan/evidence/`, and must pass before staging promotion via the go/no-go gate. Tests enforce the same boundaries the architecture promises: consent, tenant isolation, private-media protection, and retail-safe output ([ADR Pack](https://app.notion.com/p/ADR-Pack-36ff29d2a6b18108958af03b19f13a6e?pvs=21) ADR 0012).

# How to read this folder

1. Start with `README.md` for the layered strategy and the promotion gates.
2. Read the per-layer plans (`backend`, `frontend`, `storage`, `security`) for what each verifies.
3. Read `e2e-test-plan.md` for the journeys that tie the layers together.

# Principles

- **Demo-mode deterministic** — providers stubbed; same input → same result.
- **Evidence-backed** — results stored under `implementation-plan/evidence/`.
- **Gated** — all suites pass before staging promotion (`implementation-plan/checklists/`).
