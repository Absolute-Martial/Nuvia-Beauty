# 1. Purpose & scope

`vendor-portal` is the **in-store seller application** used by beauty advisors to run consented customer consultations, curate the product mappings that feed recommendation scoring, and review recommendation quality before presenting it. Like the storefront and admin-panel it is a thin client: it talks only to `backend-engine` over REST, holds no provider or storage credentials, and gates every action behind role-based Policy authorization. Seller consultation is the **Phase 4 — Seller consultation foundation** of the roadmap, and the portal degrades gracefully to demo-mode when a provider is unavailable ([ADR Pack](https://app.notion.com/p/ADR-Pack-36ff29d2a6b18108958af03b19f13a6e?pvs=21) ADR 0012, zero-trust).

# 5. Principles

- **Consent-first** — sellers act only on behalf of customers who have given explicit, revocable consent.
- **No credentials in the client** — nothing sensitive in any `NEXT_PUBLIC_*` variable.
- **No raw media** — the portal never displays beauty media or full signed URLs; media is referenced by key and handled only via short-lived signed URLs.
- **Retail-safe language** — all copy avoids clinical/medical claims (ADR 0005).
- **Zero-trust** — every action authorized by a Policy and audit-logged (ADR 0012).
- **Graceful degradation** — consultations work in demo-mode when a provider is unavailable.
