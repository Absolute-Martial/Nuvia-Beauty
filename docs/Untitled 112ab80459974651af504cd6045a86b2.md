# Untitled

<aside>
🛡️

The **governance** section is the canonical home for cross-cutting tracking that spans the whole Nuvia Beauty documentation set and repo — the things no single design doc owns.

</aside>

This section currently holds:

- **Risk & Issues Register** — the canonical tracking system for every identified issue (one record per issue, with severity, status, root cause, impact, recommended resolution, owners, and cross-links to the relevant Technical Papers, ADRs, RFCs, and Implementation Plan phases).
- **Status Matrix** — the executive dashboard view of all issues: a single screen for severity, current status, owner, and resolution approach.

<aside>
📌

The register is a **tracking mechanism**, not the place where decisions live. When an issue resolution changes architecture, scope, or implementation, the decision must also be written into the corresponding source document (HLD, ADR, Roadmap, scope doc, etc.) so the register stays a pointer, not a parallel source of truth.

</aside>
