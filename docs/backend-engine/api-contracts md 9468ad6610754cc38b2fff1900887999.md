# 1. Purpose & scope

This page defines the **API surface** `backend-engine` exposes to the storefront, admin-panel, and vendor-portal, plus the conventions that govern authentication, payload shapes, idempotency, redaction, and errors. All endpoints are authenticated and authorized via Policies; provider calls happen server-side only.

# 2. Surface (representative)

| Area | Endpoint (representative) | Purpose |
| --- | --- | --- |
| Auth | `POST /auth/login`, `POST /auth/logout` | Session/token issuance, tenant resolution |
| Media | `POST /media/upload-url` | Mint pre-signed PUT (TTL 15m) |
| Media | `POST /media/{id}/confirm` | Confirm upload, enqueue processing |
| Beauty | `POST /beauty/analyze` | Run P0 analysis (consented) |
| Sessions | `POST /sessions`, `PATCH /sessions/{id}` | Consultation lifecycle (draft/complete/discard) |
| Profile | `GET /profiles/{id}` | Saved profile + snapshot history (T1+) |
| Recommendations | `GET /recommendations` | Ranked product recommendations |
| Mapping | `GET/POST /mappings` | Seller product mappings |
| Consent | `GET/POST /consent`, `DELETE /consent/{id}` | Set / revoke tiered consent (T0–T4) |
| Quota | `GET /quota` | Tenant quota balance and events |
| Insights | `GET /insights` | Consented, aggregated brand insights |
| Catalog | `GET /products`, `GET /products/{id}` | Catalog browse + detail |
| Events | `POST /events` | Ingest interaction signals |

# 3. Recommendation payload

The canonical recommendation object, identical wherever recommendations appear:

```json
{
  "product_id": "string",
  "score": 0.0,
  "confidence": 0.0,
  "reasons": ["string"],
  "warnings": ["string"]
}
```

# 4. Error shape

Errors use a consistent problem response; no provider or internal details leak to clients:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Human-readable, safe summary",
    "details": []
  }
}
```

# 5. Conventions

- **REST-first** for all mutations, AI orchestration, and security-sensitive workflows; GraphQL is deferred to Phase 7+ as a read-only gateway only ([ADR 0014 — API strategy: REST-first, GraphQL deferred](https://app.notion.com/p/ADR-0014-API-strategy-REST-first-GraphQL-deferred-752b921b3cce49d99892294c52822432?pvs=21)).
- **OpenAPI-first** — contracts are defined before coding.
- Requests validated by Form Requests; inputs/outputs modeled as DTOs + Enums (see [[validation.md](http://validation.md)](validation%20md%20a11c1a59a2f44f339fdaee8e884154d4.md)).
- **Redaction middleware** strips `api_key`, `secret`, `signed_url`, and `raw_payload` from every response.
- **Idempotency keys** (UUID) required on risky POSTs (start analysis, deduct quota) to avoid duplicate provider billing.
- **Tenancy** — every request resolves a `shop_id` server-side; cross-tenant access is impossible from the client.
- All provider calls and private-media access route through the Zero Access Layer ([ADR 0015 — Zero Access Layer (ZAL)](https://app.notion.com/p/ADR-0015-Zero-Access-Layer-ZAL-3955db20d36940048813c2537875a5cf?pvs=21)).

# 6. Versioning

- The API is versioned; breaking changes ship behind a new version while the OpenAPI spec remains the contract of record.
