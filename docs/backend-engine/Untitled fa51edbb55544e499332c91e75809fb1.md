# 1. Purpose & scope

AI agents write much of this codebase. **Strict, machine-followable guardrails** keep them from breaking the architecture or leaking data. These rules are non-negotiable and complement the validation strategy and API conventions. See [ADR 0014 — API strategy: REST-first, GraphQL deferred](https://app.notion.com/p/ADR-0014-API-strategy-REST-first-GraphQL-deferred-752b921b3cce49d99892294c52822432?pvs=21) and [ADR 0015 — Zero Access Layer (ZAL)](https://app.notion.com/p/ADR-0015-Zero-Access-Layer-ZAL-3955db20d36940048813c2537875a5cf?pvs=21).

# 2. Foundational practices

- **OpenAPI specs first** — define REST API contracts **before** coding; agents follow exact routes better this way.
- **Redaction middleware** — every API response passes through a filter that automatically strips `api_key`, `secret`, `signed_url`, and `raw_payload` to prevent accidental AI-generated leaks.
- **Event-driven jobs** — never make AI provider calls or media processing synchronous; use Laravel Queues/Events (e.g. `AnalysisRequested`, `MediaExpired`).
- **Idempotency keys** — require a UUID idempotency key on risky POSTs (start analysis, deduct quota) to prevent duplicate provider billing if a user clicks twice.
- **Feature flags & demo mode** — a formal `DemoBeautyProvider` with seeded dummy data lets the app run and be tested without spending Perfect Corp credits.

# 3. `AGENTS.md` (repository root)

Create an `AGENTS.md` file in the repository root with these hard rules so agents don't break the architecture:

<aside>
🚫

- Do not expose secrets or raw provider JSON.
- Do not call Perfect Corp from the frontend.
- Controllers must only call Actions/Services, never DB/S3 directly.
- Do not introduce GraphQL mutations.
- Do not bypass Laravel Policies.
</aside>

# 4. Review checklist

Before merging backend changes, confirm:

- [ ]  Endpoint defined in OpenAPI before implementation.
- [ ]  Form Request + Policy present; inputs mapped to DTOs/Enums.
- [ ]  No secrets, signed URLs, or raw provider payloads in responses.
- [ ]  Provider/media work runs in a queued, idempotent job.
- [ ]  No controller touches DB/S3/providers directly.
- [ ]  PHPStan max passes.
