# What an ADR is

An Architecture Decision Record captures **one decision** in a stable, reviewable form. Each record follows the same convention so future contributors can understand not just *what* was decided but *why*, and what it costs to reverse:

- **Context** — the forces and constraints that made a decision necessary.
- **Decision** — the choice that was made.
- **Status** — `Proposed`, `Accepted`, `Superseded`, or `Deprecated`.
- **Consequences** — the trade-offs, follow-on work, and mitigations that result.

The canonical records also include rationale, alternatives considered, and mitigations on their individual sub-pages.

# Adding or superseding an ADR

1. **Add** a new record with the next sequential number (0016, 0017, …); never renumber or delete existing ADRs.
2. Author it in the [ADR Pack](https://app.notion.com/p/ADR-Pack-36ff29d2a6b18108958af03b19f13a6e?pvs=21) using the Context · Decision · Status · Consequences convention, then add a row to the index above.
3. **Supersede** rather than edit a decision that changes: set the old record's status to `Superseded by ADR-NNNN` and link forward; keep the historical record intact for traceability.
4. Keep ADRs consistent with the [High-Level Design](https://app.notion.com/p/High-Level-Design-36ff29d2a6b18142a5b4e5c386737c9f?pvs=21) and [Reference Architecture](https://app.notion.com/p/Reference-Architecture-36ff29d2a6b181a3a17ad985ffef1d0c?pvs=21); if a decision changes either, update both in the same change.
