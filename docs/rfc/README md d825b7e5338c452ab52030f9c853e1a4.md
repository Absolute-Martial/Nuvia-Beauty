# Overview

An RFC (Request for Comments) proposes a change and opens it for review **before** it is accepted. Once accepted, the durable decision is recorded as an ADR in [ADR Pack](https://app.notion.com/p/ADR-Pack-36ff29d2a6b18108958af03b19f13a6e?pvs=21).

# When to write one

- A cross-cutting change (architecture, data model, security boundary, provider strategy).
- A decision that needs buy-in or has trade-offs worth recording.

# Lifecycle

1. **Draft** — problem, options, proposal, impact.
2. **Review** — gather comments; revise.
3. **Accepted / Rejected** — outcome recorded.
4. **Captured** — accepted RFCs become an ADR.

# Suggested sections

- Context · Problem · Proposal · Alternatives · Impact (security/storage/cost) · Rollout · Open questions.
