# 1. Purpose & scope

`storefront` is the **customer-facing Progressive Web App**. It powers catalog browsing, confidence-driven recommendations, optional consented self-scan, and the try-on studio. It is a thin client: it talks only to `backend-engine` over REST and **never holds provider or storage credentials**. PWA-first delivery is the platform decision in [ADR Pack](https://app.notion.com/p/ADR-Pack-36ff29d2a6b18108958af03b19f13a6e?pvs=21) ADR 0001.

# 4. Principles

- **Consent-first** — no beauty analysis without explicit, revocable consent.
- **No credentials in the client** — nothing sensitive in any `NEXT_PUBLIC_*` variable.
- **Private media via signed URLs only** — the browser uploads/downloads via short-lived signed URLs, never with storage credentials.
- **Retail-safe language** — all copy avoids clinical/medical claims (ADR 0005).
- **Graceful degradation** — every flow works in demo-mode when a provider is unavailable.

# 5. Performance targets

- Upload-slot request &lt; 500 ms; recommendation generation &lt; 1 s (server-side budgets the storefront depends on).
